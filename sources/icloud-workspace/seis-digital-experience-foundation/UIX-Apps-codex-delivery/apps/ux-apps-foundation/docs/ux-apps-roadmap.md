# UX Apps Roadmap

This repository starts as a dependency-free UX application surface. Each future app should stay small, useful, and easy to review.

## Phase 1 - Static Foundation

- Build the first app catalog.
- Keep search and filters client-side.
- Add a local quality check.
- Preserve direct browser opening support.

## Phase 2 - App Modules

- Convert each catalog item into a focused app folder.
- Add local examples for journey maps, audit reports, and release decisions.
- Keep data portable and editable without a database.

## Phase 3 - Review Artifacts

- Add UX audit templates.
- Add accessibility review checklists.
- Add product decision logs.
- Add compact export formats for stakeholder review.

## Phase 4 - Zip Source Intake

- Use `/Users/emirhan/Downloads/Github a gönderilecekler.zip` as a reviewed source inventory.
- Promote only source files, patterns, content, and design ideas that fit the UX Apps architecture.
- Keep generated artifacts, dependency folders, framework build output, and metadata outside the repo.
- Record each imported idea in `docs/github-handoff.md` or the long-term program before implementation.

## Phase 5 - Cinematic And 3D UX Layer

- Add restrained depth, spatial hierarchy, and cinematic transitions without overwhelming cognition.
- Prefer CSS, Canvas, and lightweight native browser APIs before proposing a 3D dependency.
- Keep every motion path responsive, GPU-conscious, and compatible with `prefers-reduced-motion`.
- Build 3D as a usability layer, not decorative spectacle.

## Phase 6 - Full-Stack Product Maturity

- Expand API-backed UX tools gradually.
- Add durable local examples for journey maps, accessibility checks, product decisions, and release reviews.
- Improve observability endpoints and data contracts before adding infrastructure.
- Preserve the current native Node/static foundation as the rollback baseline.

## Guardrails

- No dependency bloat without a clear app-level reason.
- No heavy animation by default.
- No private user research data committed to git.
- No broad rewrites when a focused app module is enough.
- No raw zip mirroring; every promoted file or idea must be reviewed and adapted.
