# SEIS Supreme Operating Directive

Status: active foundation directive  
Mission: `SEIS-M001`  
Date: 2026-05-31

SEIS, Smart Ecosystem for Integrated Systems, is an AI-assisted Creative Technology Operating System. It is not a website, portfolio, or simple repository. It is a long-term operating model that combines creative practice, software engineering, AI systems, automation, research, documentation, knowledge management, governance, and GitHub workflows.

## Purpose

This directive defines the permanent operating rules for evolving SEIS through small, reversible, architecture-aware missions.

SEIS must grow as:

- GitHub repository
- knowledge system
- workflow engine
- AI assistant team
- documentation system
- token-efficient architecture
- long-term evolution system

## Laws

### Law 001: Single Active Mission

Only one implementation mission may be active at a time.

Every mission must pass through:

`Research -> Analysis -> Planning -> Architecture -> Implementation -> Validation -> Documentation -> Commit -> Completion`

No second implementation mission should begin until the active mission reaches completion or is explicitly paused.

### Law 002: Model Independence

Models are replaceable. Roles are permanent.

SEIS may use Codex, Gemini, Claude, or future models as execution engines, but the system depends on architecture, agent roles, governance, and records rather than one provider.

### Law 003: GitHub Living Repository

GitHub is the primary source of truth for:

- code
- documentation
- workflows
- registries
- prompts
- governance
- architecture

iCloud and Google Drive are archive layers for large assets, exports, backups, creative source files, and ZIP packages.

## Storage Rules

GitHub should hold:

- code
- markdown
- JSON registries
- workflows
- prompts
- governance files
- architecture records

iCloud and Google Drive should hold:

- PSD
- AI
- INDD
- MP4
- MOV
- ZIP
- exports
- backups
- large source archives

Local folders are temporary workspaces unless promoted through a mission.

## Branch Rules

`main` remains sacred and production-safe.

`UIXAppTTR` remains the active SEIS/UIXApps foundation branch until the governance model is changed through a dedicated mission.

Mission branches may be used for risky work, but long-lived branch sprawl is not allowed. Sub-agent work should be tracked through registries when possible.

## Technology Rule

SEIS may support many languages and stacks, but technologies activate only when a mission needs them.

Adding a technology requires:

- mission purpose
- domain owner
- validation command
- rollback path
- documentation note

## Knowledge Rule

SEIS must never load or import the entire knowledge base by default.

The active context should follow:

`Mission -> Intent Detection -> Domain Detection -> Context Routing -> Relevant Files Only -> Execution`

The system goal is:

`Large Knowledge Base -> Small Active Context`

## Current Mission

`SEIS-M001` establishes the foundation governance layer:

- supreme directive
- mission control registry
- domain map
- agent role registry
- token routing map
- workflow lifecycle documentation

This mission does not introduce product features. It creates the operating system layer that future missions will use.
